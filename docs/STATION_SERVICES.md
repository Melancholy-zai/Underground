# 深圳站点服务资料

本次整理日期：2026-09-28。资料随 App 内置，采集器只在开发电脑运行。

## 实际收录

432个官方查询编号均取得动态响应，关联既有351个站点、17条编号线路。最终收录2595条时刻和1699个出口条目；每个站点都有已收录的时刻和出口。时刻条数包括工作日、休息日、未注明具体日期的节假日参考、运营方表中的全程和半程服务，不代表2595个不同班次。

431/432个线路内站次有可展示的结构化时刻。科学馆6号线的动态首班与6月1日起的调整公告不同，相关动态行暂时隔离，公告首班06:10仍作为独立日期说明展示。41个出口只有可靠编号或部分信息，没有道路及地标描述；全部出口均无精确坐标，不提供精确出口导航。

逐站、逐线路结果：

- `data/shenzhen/references/station-services/coverage.csv`：432个站次，包含方向、适用条件、条目数量、分类状态与缺口。
- 同目录 `coverage.json`：全网与各线路计数。
- 同目录 `GAPS.md`：可直接阅读的逐站缺口表。
- 同目录 `normalization-audit.json`：原始字段位置、查询编号、SHA-256、候选、隔离依据及结果。

## 可重复流程

联网采集，成功缓存不重复请求，失败记录保留：

```sh
python3 tools/collect_station_services.py
python3 tools/collect_operator_services.py --fetch
```

动态查询顺序执行、默认间隔至少1.1秒；连接失败可以再次运行补采。401／403／429或非预期页面会停止，不绕过访问限制。`requests`保存当前结果，`request-history.jsonl`保留历次尝试，`raw`保存原文。使用`--refresh`前必须明确需要更新；更新原图后需要重新核读，不能沿用旧摘录。

离线重建：

```sh
python3 tools/collect_operator_services.py --build
python3 tools/normalize_station_services.py
python3 tools/collect_shenzhen.py
python3 tools/citypack.py build data/shenzhen/source.json App/Resources/CityPack
bash scripts/check.sh
```

归一化按固定stationID合并；同方向、适用条件的不同时间不按请求先后覆盖。结构化输入位于`station-services/services.json`，生成器要求其完整关联351个固定站点，缺失时报错，不回退为空数组。

schemaVersion升级为2，兼容读取1；Swift模型、Python校验、manifest版本、哈希校验和加载器同步。首末班区按线路和方向显示“日期／首班／末班”表格，特殊日期公告默认收起；隐藏重复收录说明、整理时间及来源链接，删除详情底部“资料说明”。原始来源、日期、冲突和状态仍保留在数据包。出口内容本轮保持，动态查询来源改为普通文字，不再跳转。图形和导航坐标没有随服务资料改动。

显示合并仅用于4号线“平日和周末”全程表：当工作日和休息日两份表的时间及生效范围均一致时，隐藏重复的合并表。半程、时间不同、日期不同和“适用日未注明”的记录均保留，不改变实际资料。
