# 站点时刻异常与日期公告核查

核查日期：2026-09-28。核验者：Codex source audit。机器可读记录见 [anomalies.json](../data/shenzhen/references/station-services/anomalies.json)。本次只写研究输入，不修改地图、站点归属或正式时刻。

## 结论

- **莲塘方向／线路冲突未解决**：已核对完整官方响应，不能将额外8号线行用于修改地图归属，也没有足够证据给冲突字段填写替代值。
- **溪涌“梧桐山南”未获实际终点证明**：官方资料可以确认2／8号线贯通运营，不能据此证明本站某班首末车最终到哪里。保留候选原值，不自动改为赤湾，也不把梧桐山南写成末班终点。
- **9月24日公告适用7个离散日期**：9月28日不在其中。20号线不适用；“不早于”和“零点前后”只保存带日期的文字说明。
- 另找到 **6月1日起的6号线首班调整、坪地六联往华新的半程服务**。可作为明确日期的补充依据；新增公告事实与当前动态全表的核验是两回事。

所有下列在线来源访问日期（`accessedAt`）均为2026-09-28。原始查询的秒级时间、哈希、字段定位保存在JSON；没有给未注明生效日的查询资料补造日期。

| 工作日 | 赤湾05:57—23:29；莲塘06:16—23:57 | 梧桐山南05:57—23:29；溪涌06:16—23:57 |

上表按原始字符串记录；节假日表没有具体适用日期，也未因此认证这组分钟为当前节假日安排。

官网脚本第277—280行把旧查询编号0801改为0232。说明官网确有莲塘的兼容查询行为，但它不能证明每一行方向正确，也不是给项目莲塘添加8号线归属的依据。

另查深铁[2号线无障碍设施](https://www.szmc.net/szmc_m/shentieyunying/yunyingzixun/wuzhangaichengchezhinan/line2/)与[8号线无障碍设施](https://www.szmc.net/szmc_m/shentieyunying/yunyingzixun/wuzhangaichengchezhinan/Line8/)：前者列莲塘，后者从梧桐山南开始；2号线页的世界之窗、景田站同时使用“8号线溪涌方向”站台导向。这支持区分“线路归属”与“贯通列车导向”，没有支持莲塘具体首末班字段的唯一修正方案。

**处理建议**：保留六条原始行；至少隔离额外8号线行与2号线指向本站“莲塘”的方向。2号线赤湾方向可单独审阅，不能因为同响应有冲突就改写它。出口A、C、D与时刻分开处理，不因方向冲突丢弃。`adjustedValue=null`，本次没有应用方向覆盖。

## 2. 溪涌：方向标签不能证明实际终到站

来源：[官方站点入口](https://www.szmc.net/shentieyunying/yunyingfuwu/zhandianchaxun/?0812)。已读取 `raw/0812.json` 与请求记录，取得时间为2026-09-28 16:05:58 +08:00。

- 工作日原始值：8号线、梧桐山南方向，05:54—22:56。
- 休息日原始值：同一标签，05:57—22:56。
- 来源节假日参考表：同一标签，05:57—23:56，适用日期未注明。
- 另一方向“溪涌”的首末均为`--`；不能转换成00:00。

[深铁新线开通报道](https://www.szmc.net/home/xinwenzhongxin/gongsixinwen/202512/105561.html)明确8号线三期于2025-12-28开通，并与2／8号线贯通；[交通局线路资料](https://jtys.sz.gov.cn/ydmh/jtcx/dtcx_180970/dtxl/content/post_12601090.html)将2&8号线列为赤湾至溪涌的连续站序。前文的运营方站台导向也支持这一关系。开通报道搜索摘要的页头为2025-12-29，实际打开页头为2025-12-25，两者不一致，故JSON发布日期留空；开通事件日期依据正文，二者分开记录。

这些证据**没有列出溪涌上述分钟对应班次的实际终点**。因此无法排除首班、全程末班、半程或回库服务间的差异。也未找到直接证明梧桐山南就是本站末班实际终点的运营方资料。

**处理建议**：保留原始候选时间和标签；`lastDestination`保持未知。若详情页面只能把该标签展示为已确认方向/终点，应隔离这组时刻，继续独立收录出口。禁止全局“梧桐山南→赤湾”替换。中文溪涌的英文字段仍为`Yantian Rd`，也提示响应文本可能保留历史标签，但这不是推断任一中文替代值的依据。
